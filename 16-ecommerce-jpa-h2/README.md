# 16 - eCommerce Project with Spring Data JPA and H2

The next stage of my eCommerce project (`sb-ecom`). In
[15-ecommerce-project](../15-ecommerce-project) the categories were stored in
a Java list. Here they are stored in a **real database** using Spring Data JPA
and H2, with no change to the API.

## Tech Stack

Java 17 | Spring Boot 3.2.5 | Spring Web | Spring Data JPA | Hibernate | H2 Database | Maven | IntelliJ IDEA | Postman

## What Changed, Step by Step

| Step | What I added | Concept |
|------|--------------|---------|
| 1 | Configure the project for JPA | `spring-boot-starter-data-jpa`, H2 dependency |
| 2 | Turn `Category` into an entity | `@Entity`, `@Id` |
| 3 | Database settings | `application.properties`, H2 console, datasource URL |
| 4 | Generated ids | `@GeneratedValue`, `GenerationType.IDENTITY` |
| 5 | JPA repository | `CategoryRepository extends JpaRepository` |
| 6 | Persistent categories | Service uses `findAll`, `save`, `delete` instead of a list |
| 7 | Optionals in the service | `findById(...).orElseThrow(...)` |
| 8 | Experimenting | `show-sql` and `format_sql` to see the SQL Hibernate runs |

## Before and After

| | 15 (in-memory) | 16 (JPA + H2) |
|---|---|---|
| Where categories live | `ArrayList` in the service | `categories` table in H2 |
| Finding a category | Stream and `filter` | `categoryRepository.findById(id)` |
| Saving | `list.add(...)` | `categoryRepository.save(...)` |
| Ids | Counter in the service | Generated by the database |
| `Category` class | Plain Java class | JPA entity |

The controller and the four endpoints stay the same.

## API Endpoints

| Method | URL | Body | Success response |
|--------|-----|------|------------------|
| GET | `/api/public/categories` | none | `200 OK` and the list of categories (JSON) |
| POST | `/api/public/categories` | `{"categoryName": "Electronics"}` | `201 Created` |
| PUT | `/api/public/categories/{categoryId}` | `{"categoryName": "Books"}` | `200 OK` |
| DELETE | `/api/admin/categories/{categoryId}` | none | `200 OK` |

If the category id does not exist, PUT and DELETE return `404 Not Found`
with a message.

## Key Code

**The entity** (`Category.java`)

```java
@Entity(name = "categories")
public class Category {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long categoryId;
    private String categoryName;
    ...
}
```

`@Entity` maps the class to a table, `@Id` marks the primary key, and
`IDENTITY` lets the database generate the id. JPA also needs a no-argument
constructor, so `Category()` was added.

**The repository** (`CategoryRepository.java`)

```java
public interface CategoryRepository extends JpaRepository<Category, Long> {
}
```

No code needed. `JpaRepository` already gives `findAll`, `findById`, `save`,
`delete` and more, and Spring creates the implementation.

**Using the repository in the service** (`CategoryServiceImpl.java`)

```java
@Autowired
private CategoryRepository categoryRepository;

public List<Category> getAllCategories() {
    return categoryRepository.findAll();
}

public String deleteCategory(Long categoryId) {
    Category category = categoryRepository.findById(categoryId)
            .orElseThrow(() -> new ResponseStatusException(
                    HttpStatus.NOT_FOUND, "Resource not found"));
    categoryRepository.delete(category);
    return "Category with categoryId: " + categoryId + " deleted successfully !!";
}
```

`findById` returns an `Optional`. `orElseThrow` gives the category or throws a
404 if it does not exist.

**Database settings** (`application.properties`)

```properties
spring.h2.console.enabled=true
spring.datasource.url=jdbc:h2:mem:test
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

## How to Run

1. Open this folder in IntelliJ IDEA (Java 17+, Maven).
2. Let Maven download the dependencies.
3. Run `SbEcomApplication.java`.
4. Test the endpoints in Postman at `http://localhost:8080/api/public/categories`.

## Viewing the Database

With the app running, open the H2 console at
`http://localhost:8080/h2-console` and use the JDBC URL `jdbc:h2:mem:test`.
Run `SELECT * FROM categories;` to see the saved data. The SQL that Hibernate
runs is also printed in the IntelliJ console.

## Notes

- H2 is an **in-memory** database, so the data is cleared every time the app
  restarts. A production database such as MySQL is the natural next step.

## What I Learned

- Mapping a class to a database table with JPA annotations
- Using Spring Data JPA repositories instead of writing SQL
- Letting the database generate ids
- Handling "not found" with `Optional` and `ResponseStatusException`
- Viewing the generated SQL and the database through the H2 console
